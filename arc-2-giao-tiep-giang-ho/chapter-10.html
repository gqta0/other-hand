Phần 1: Đại Hội Giao Lưu API (5 phút)

Người kể chuyện

Hôm nay là ngày cuối cùng Lâm Tuấn lưu lại Cổng Giao Tiếp trước khi bước vào Tàng Kinh Các (Security). Sư Phụ Cao Nhân triệu tập anh đến Đài Quan Sát. Phía dưới, hàng loạt các cỗ máy (Mobile App, Frontend App) đang bay lượn, chờ đợi được kết nối.

Sư Phụ Cao Nhân

Tuấn nhi, những cỗ máy kia không biết đọc HTML của ngươi đâu. Chúng cần dữ liệu tinh khiết - JSON. Nhiệm vụ hôm nay của ngươi là chuyển đổi toàn bộ hệ thống Quản Lý Đệ Tử sang chuẩn RESTful API.

Lâm Tuấn

Đệ tử hiểu! Thay vì dùng `@Controller` trả về View, đệ tử sẽ dùng `@RestController`. Thay vì trả về `String` (tên file), đệ tử sẽ trả về `List` hoặc `Disciple`.

Sư Phụ Cao Nhân

Đúng, nhưng chưa đủ. Một bộ API chuẩn phải tuân thủ nghiêm ngặt các quy tắc về HTTP Method và Status Code. Hãy bắt tay vào làm!

Phần 2: Xây Dựng CRUD API (10 phút)

Lâm Tuấn

Đầu tiên, đệ tử tạo class `DiscipleRestController`. Gốc đường dẫn đệ tử đặt là `@RequestMapping("/api/disciples")`.

Sư Phụ Cao Nhân

Tốt. Bắt đầu với việc Lấy Danh Sách.

Lâm Tuấn

Đệ tử dùng `@GetMapping`. `public List getAll() { return discipleService.findAll(); }`

Sư Phụ Cao Nhân

Được. Tiếp theo, Lấy Chi Tiết một người.

Lâm Tuấn

`@GetMapping("/{id}")`. Đệ tử dùng `@PathVariable` để lấy ID. Nhưng thưa Sư Phụ, nếu không tìm thấy ID thì sao?

Hộ Pháp MVC

Hãy dùng `ResponseEntity`. Nếu tìm thấy -> `return ResponseEntity.ok(disciple)`. Nếu không -> `return ResponseEntity.notFound().build()`. Đừng trả về null, Client sẽ không hiểu đâu!

Sư Phụ Cao Nhân

Tiếp tục. Tạo Mới.

Lâm Tuấn

`@PostMapping`. Dữ liệu gửi lên là JSON, nên đệ tử dùng `@RequestBody` (chứ không phải @ModelAttribute nữa). `public ResponseEntity create(@RequestBody Disciple d)` Sau khi lưu xong, đệ tử trả về status `201 Created`.

Sư Phụ Cao Nhân

Rất chuyên nghiệp!

Phần 3: Cập Nhật và Xóa (Update & Delete) (8 phút)

Lâm Tuấn

Với Cập Nhật, đệ tử dùng `@PutMapping("/{id}")`. Đệ tử cần cả `@PathVariable` (để biết sửa ai) và `@RequestBody` (để biết sửa cái gì). Logic: Tìm xem ID có tồn tại không. Nếu có thì update, nếu không thì trả về 404.

Sư Phụ Cao Nhân

Cuối cùng, Hủy Diệt.

Lâm Tuấn

`@DeleteMapping("/{id}")`. Sau khi xóa thành công, đệ tử trả về `204 No Content` hoặc `200 OK` kèm thông báo.

Người kể chuyện

Hệ thống API đã hoàn tất. Nhưng làm sao để thử nghiệm khi không có giao diện? Hộ Pháp MVC rút ra một phi kiếm đưa cho Lâm Tuấn.

Hộ Pháp MVC

Hãy dùng phi kiếm này - tên nó là Postman (hoặc Curl). Dùng nó để bắn các luồng JSON vào API của ngươi và xem phản hồi. Ví dụ: Bắn `POST /api/disciples` với body `{ "name": "Lâm Tuấn", "level": "Junior" }`.

Phần 4: Tổng Kết Arc 2 (7 phút)

Sư Phụ Cao Nhân

Chúc mừng Tuấn nhi! Ngươi đã hoàn thành Arc 2: Giao Tiếp Giang Hồ. Ngươi đã nắm vững DispatcherServlet, RequestMapping, View với Thymeleaf, và đỉnh cao là REST API. Giờ đây, ứng dụng của ngươi đã có thể giao tiếp với cả thế giới.

Lâm Tuấn

Nhưng Sư Phụ, đệ tử lo lắng. Cổng thành mở rộng như vậy, nếu kẻ xấu (Hacker) trà trộn vào xóa hết dữ liệu thì sao? Đệ tử chưa hề có chốt bảo vệ nào cả!

Sư Phụ Cao Nhân

Đó chính là nội dung của Arc tiếp theo: Spring Security - Phòng Hộ Sơn Môn. Chúng ta sẽ xây dựng tầng tầng lớp lớp bảo vệ, từ việc nhận diện khuôn mặt (Authentication) đến phân chia quyền hạn (Authorization). Hãy nghỉ ngơi, ngày mai sẽ là một ngày sóng gió.

📚 Tổng Kết Arc 2

  • RESTful API Kiến trúc thiết kế API dựa trên Resource (URL) và Method (như GET, POST).
  • @RequestBody Phù Chú chuyển đổi JSON từ Request Body thành Java Object.
  • HTTP Status Codes Mã trạng thái: 200 OK, 201 Created, 400 Bad Request, 404 Not Found, 500 Server Error.
  • Idempotency Tính chất: Thực hiện hành động nhiều lần kết quả vẫn như nhau (GET, PUT, DELETE). POST không Idempotent.

💼 Câu Hỏi Phỏng Vấn Tổng Hợp

  1. Sự khác biệt giữa @Controller và @RestController?
  2. Khi nào dùng @RequestBody, khi nào dùng @ModelAttribute?
  3. Giải thích ý nghĩa các HTTP Method: GET, POST, PUT, DELETE, PATCH.
  4. HTTP Status Code 401 và 403 khác nhau thế nào? (Sẽ học kỹ ở Arc 3).
