Chapter 33: Huyễn Thuật Giả Lập

📖 Spring Boot Test & @MockBean ⏱️ 30 phút

Phần 1: Khởi Động Thế Giới Ảo (@SpringBootTest) (8 phút)

Sư Đệ Minh

Unit Test rất nhanh, nhưng nó có điểm yếu chí mạng: Nó tin tưởng tuyệt đối vào Mock. Nếu Mock bảo "A gọi B đúng", nhưng thực tế trong Spring, A không thể gọi B (do thiếu Bean, sai Config), thì Unit Test vẫn xanh, nhưng App chạy lên thì sập.

Lâm Tuấn

Vậy ta phải test cả App thật?

Sư Đệ Minh

Đúng. Ta dùng @SpringBootTest. Khi có annotation này, Spring sẽ khởi động toàn bộ ApplicationContext (như lúc chạy thật). Nó quét, tạo Bean, inject dependency đầy đủ. Nhưng cái giá phải trả là thời gian khởi động lâu (vài giây đến chục giây).

Phần 2: Giả Lập Một Phần Tử (@MockBean) (10 phút)

Lâm Tuấn

Nhưng đệ tử không muốn kết nối đến Database thật, hay gọi API bên thứ ba (Third-party) trong lúc test. Làm sao để vừa chạy Spring, vừa thay thế vài Bean cụ thể bằng đồ giả?

Sư Đệ Minh

Dùng tuyệt chiêu @MockBean. Nó khác `@Mock` của Mockito nhé. - `@Mock` (Mockito): Tạo object giả trong môi trường Java thuần. - `@MockBean` (Spring): Tìm trong Spring Context, GỠ Bean thật ra, LẮP Bean giả vào. Đây là chiêu "Tráo Long Tráo Phụng". Các bean khác vẫn là thật, chỉ riêng bean bị mock là giả.

Lâm Tuấn

Vậy đệ tử có thể `@SpringBootTest` + `@MockBean UserRepository`. Logic Service chạy thật, nhưng khi gọi xuống DB thì gặp Mock. Quá tuyệt vời!

Phần 3: Cắt Lớp Thử Nghiệm (Test Slices) (7 phút)

Sư Đệ Minh

Tuy nhiên, `@SpringBootTest` vẫn quá nặng nề nếu huynh chỉ muốn test mỗi Controller. Spring cung cấp các "Lát cắt" (Slices) nhẹ hơn: 1. @WebMvcTest: Chỉ khởi động tầng Web (Controller, Interceptor, Filter). Không khởi động Service hay Repository. 2. @DataJpaTest: Chỉ khởi động tầng Data (Entity, Repository, DataSource in-memory h2). Không khởi động Web.

Lâm Tuấn

À, dùng dao nhỏ mổ gà, dùng dao to mổ trâu. Nếu test Controller API, đệ tử sẽ dùng `@WebMvcTest`. Khi đó Service phải dùng `@MockBean`. Rồi dùng `MockMvc` để giả lập gửi Request HTTP (GET, POST).

Phần 4: Tổng Kết (5 phút)

Người kể chuyện

Lâm Tuấn đã nắm trong tay các công cụ mạnh mẽ: - Testing Pyramid: Unit Test nhiều nhất (đáy tháp), Integration Test vừa phải, E2E Test ít nhất (đỉnh tháp). - Công cụ: Mockito cho Unit, @SpringBootTest/@MockBean cho Integration.

Sư Đệ Minh

Có một vấn đề cuối cùng. Dùng H2 Database (In-memory) để test Repository rất nhanh, nhưng nó KHÔNG giống MySQL thật. Có những câu SQL chạy được trên H2 nhưng lỗi trên MySQL (hoặc ngược lại). Muốn an tâm tuyệt đối, huynh phải test trên Database thật. Nhưng lại phải sạch sẽ, dùng xong vứt đi. Đó là lúc huynh cần đến TestContainers.

📚 Thuật Ngữ Chương Này

  • @SpringBootTest Annotation dùng cho Integration Test. Khởi động toàn bộ Spring Context. Rất mạnh nhưng chậm.
  • @MockBean Annotation của Spring Boot dùng để replace một Bean trong Context bằng Mockito Mock.
  • @WebMvcTest Test Slice dành riêng cho tầng Web (Controller). Chỉ load các bean liên quan đến Web.
  • MockMvc Công cụ để giả lập HTTP Request gửi đến Controller mà không cần start Server thật trên port 8080.

💼 Câu Hỏi Phỏng Vấn

  1. Sự khác nhau giữa @Mock và @MockBean? (@Mock dùng cho Unit Test thuần Java. @MockBean dùng để thay thế Bean trong Spring Context Integration Test).
  2. @WebMvcTest có load Service Bean không? (Không. Bạn phải tự mock Service bằng @MockBean nếu Controller cần dùng).
  3. Làm sao để test Controller mà không cần start server? (Dùng MockMvc).
  4. Integration Test là gì? (Test sự tương tác giữa các component hoặc với hệ thống bên ngoài như DB, MQ).

🔮 Tiếp Theo

Lâm Tuấn sẽ học cách triệu hồi Docker Container ngay trong code Java để tạo ra một môi trường test MySQL thật 100%. Đây là kỹ thuật đỉnh cao mà mọi công ty lớn đều dùng.
