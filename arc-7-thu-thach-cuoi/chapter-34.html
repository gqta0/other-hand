📖 TestContainers & Docker ⏱️ 35 phút

Phần 1: Những Chiếc Hộp Thần Kỳ (Docker Containers) (8 phút)

Người kể chuyện

Sư Đệ Minh dẫn Lâm Tuấn đến một kho hàng khổng lồ chứa hàng triệu chiếc hộp container. Trên mỗi chiếc hộp ghi tên một loại công nghệ: MySQL, Redis, Kafka, ElasticSearch...

Sư Đệ Minh

Huynh muốn test `DiscipleRepository` với MySQL thật đúng không? Thay vì hì hục cài MySQL vào máy, ta sẽ dùng phép thuật để triệu hồi một chiếc hộp MySQL (Docker Container) ngay trong lúc chạy test. Đây là TestContainers.

Lâm Tuấn

Nghe có vẻ phức tạp. Đệ tử có cần cài Docker không?

Sư Đệ Minh

Có, nhưng code Java thì cực đơn giản. Chỉ cần khai báo `@Container` static, và chọn loại Database huynh muốn. Khi Test bắt đầu -> Hộp mở ra -> Database sẵn sàng. Khi Test kết thúc -> Hộp biến mất -> Dữ liệu sạch sẽ.

Phần 2: Thiết Lập TestContainers (12 phút)

Lâm Tuấn

Đệ tử thử viết code: `@Testcontainers` `@SpringBootTest` `class DiscipleRepoTest {` ` @Container` ` static MySQLContainer mysql = new MySQLContainer<>("mysql:8.0");` ` @DynamicPropertySource` ` static void configureProps(DynamicPropertyRegistry registry) {` ` registry.add("spring.datasource.url", mysql::getJdbcUrl);` ` // ... username, password` ` }` `}`

Sư Đệ Minh

Xuất sắc! Hàm `configureProps` sẽ lấy địa chỉ IP và Port động của Container (vì Docker map port ngẫu nhiên) và bơm vào Spring Environment. Như vậy, ứng dụng Spring của huynh sẽ kết nối thẳng vào cái hộp MySQL đó. Giờ đây, huynh có thể test những câu SQL đặc thù của MySQL (như JSON, GeoSpatial) mà H2 phải bó tay.

Phần 3: Tốc Độ vs Sự Chính Xác (10 phút)

Lâm Tuấn

Nhưng thưa sư đệ, mỗi lần chạy test nó lại phải kéo Image về và khởi động Container, mất cả chục giây. Có cách nào nhanh hơn không?

Sư Đệ Minh

Đó là sự đánh đổi (Trade-off). Muốn chính xác tuyệt đối (giống Production) thì phải chấp nhận chậm. Tuy nhiên, ta có thể tối ưu bằng cách dùng Singleton Container Pattern. Tức là khởi động Container 1 lần duy nhất, và dùng chung cho tất cả các Test Class. Hoặc dùng tính năng "Reusability" của TestContainers (beta).

Lâm Tuấn

Đệ tử hiểu rồi. TestContainers dùng cho Integration Test quan trọng (CI/CD pipeline), còn lúc code bình thường thì dùng H2 hoặc Unit Test cho nhanh.

Phần 4: Tổng Kết (5 phút)

Người kể chuyện

Lâm Tuấn cảm thấy mình đã trang bị đầy đủ vũ khí tận răng. Unit Test để mài sắc logic. Integration Test với TestContainers để đảm bảo thực chiến. Sư Đệ Minh gật đầu hài lòng, đưa cho anh tấm lệnh bài cuối cùng.

Sư Đệ Minh

Sư huynh đã sẵn sàng. Sư phụ đang đợi huynh ở đỉnh núi. Đó là bài kiểm tra cuối cùng để huynh chính thức trở thành một Spring Boot Senior Developer.

📚 Thuật Ngữ Chương Này

  • TestContainers Thư viện Java hỗ trợ JUnit tests, cung cấp các instance nhẹ của Database, Message Broker... chạy trong Docker container.
  • Docker Nền tảng containerization, cho phép đóng gói ứng dụng và môi trường chạy vào các "hộp" (container) cô lập.
  • @DynamicPropertySource Annotation dùng để ghi đè (override) các property trong application.properties bằng giá trị động runtime (ví dụ port của container).
  • Singleton Container Pattern Mẫu thiết kế để khởi động container 1 lần và dùng chung, giúp giảm thời gian chạy test suite.

💼 Câu Hỏi Phỏng Vấn

  1. Tại sao nên dùng TestContainers thay vì H2 Database? (Vì H2 không tương thích 100% cú pháp SQL với MySQL/Postgres, dễ bỏ lọt bug database-specific).
  2. Làm sao để inject URL của container vào Spring Datasource? (Dùng @DynamicPropertySource).
  3. TestContainers có yêu cầu cài Docker trên máy chạy test không? (Bắt buộc phải có Docker Daemon đang chạy).
  4. Khi nào KHÔNG nên dùng TestContainers? (Khi cần feedback loop cực nhanh trong lúc dev feature nhỏ, hoặc máy dev quá yếu không chạy nổi Docker).
